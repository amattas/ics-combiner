cache ¶

Cache layer for ICS Combiner.

Cache is the facade the app uses. It serializes values as JSON, keeps hit/miss statistics, and never raises into the request path: backend errors are logged (rate limited), counted in CacheStats.errors, and turned into misses.

Backends: - PostgresBackend: a table in the service's own PostgreSQL database (DATABASE_URL). Connects lazily, backs off for 30 s after any database error, and creates its table on first use. - MemoryBackend: a process-local dict for local development and tests (CACHE_BACKEND=memory).

PostgresBackend ¶

PostgresBackend(conninfo: str, clock: Callable[[], float] = time.monotonic)

Cache table in PostgreSQL via a small sync connection pool.

Constructing it does no I/O. The pool opens on the first operation, the table is created once per process after the first successful connect, and any database error starts a 30 s backoff during which every operation is a miss and is_connected() is False (it never does I/O itself).
